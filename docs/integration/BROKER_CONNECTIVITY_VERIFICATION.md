# Broker API Connectivity Verification

This document outlines the process for verifying broker API connectivity in the Viewzenix1 application.

## Overview

Broker connectivity verification involves checking that:
1. The application can authenticate with the broker API using the provided credentials
2. The application can retrieve account information
3. WebSocket connections for market data streaming are functioning properly

## Prerequisites

Before starting the verification process, ensure:
- You have valid API credentials (key and secret) for the broker
- The credentials are configured in your environment (.env file)
- All dependencies are installed (particularly websocket-client for streaming)

## Configuration

### .env File Setup

The following environment variables must be configured in your `.env` file:

```
# For Alpaca (primary broker)
ALPACA_API_KEY=your_api_key
ALPACA_API_SECRET=your_api_secret
USE_PAPER_TRADING=True
```

**Note**: For development and testing, always set `USE_PAPER_TRADING=True` to avoid real money transactions.

## Verification Process

### Using the Verification Tool

We provide a utility tool to verify broker connectivity. Run:

```bash
# From the project root directory
python -m src.integration.utils.stream_adapter_verification
```

This tool will:
1. Attempt to authenticate with the broker API
2. Retrieve account information
3. Verify WebSocket connectivity
4. Provide a detailed report of the results

## Troubleshooting

### API Connectivity Issues

If authentication fails:
1. Verify your API key and secret are correct
2. Ensure the API keys have not expired
3. Check that you are connecting to the correct environment (paper vs. live)
4. Verify your internet connection and firewall settings

### WebSocket Issues

If WebSocket connections fail:
1. Check that the websocket-client package is installed
2. Verify your API keys have streaming data permissions
3. Ensure your network allows WebSocket connections
4. Check if there are any broker-side outages reported

## Reporting Verification Results

After running the verification:
1. Save the results JSON file generated by the tool
2. If any issues were found, document them clearly
3. Include verification results in PR comments when applicable

## Scheduled Verification

Verification should be performed:
1. After any changes to broker integration components
2. When updating broker API dependencies
3. Before and after deployments
4. As part of automated CI/CD pipelines
